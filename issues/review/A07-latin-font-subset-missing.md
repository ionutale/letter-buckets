# The Latin subset of Nunito is never loaded, so ordinary text renders in the fallback font

- **Severity:** medium
- **Area:** build
- **Location:** `src/lib/styles/base.css:4-11` (imports), `src/lib/styles/base.css:1-3` (comment)
- **Confidence:** certain

## What happens

`base.css` imports only the `latin-ext` and `cyrillic` subsets of Nunito. The `latin-ext` webfont does not contain the basic Latin block (U+0000–00FF), and the per-subset stylesheets generated by fontsource contain **no** `unicode-range`, so the browser matches the `latin-ext` face for every character, finds no glyph for `a`–`z`, `0`–`9` or ASCII punctuation, and falls back to `system-ui` per glyph. The result is mixed typography inside single words: Romanian `ă` (U+0103, in latin-ext) renders in Nunito while `â`/`î` (U+00E2/U+00EE, in latin) render in the system font; German `ä`/`ö`/`ü` fall back while the surrounding letters do not. The visual identity of the game is lost for most of the UI text.

## Evidence

```css
/* src/lib/styles/base.css:1-11 */
/* Nunito carries Latin Extended (Romanian ă â î ș ț, German ä ö ü) and
   Cyrillic (Russian). Both subsets are self-hosted; the unicode-range in each
   face keeps the download to the glyphs the locale actually needs. */
@import '@fontsource/nunito/latin-ext-400.css';
...
@import '@fontsource/nunito/cyrillic-800.css';
```

The comment is not accurate for these files. `node_modules/@fontsource/nunito/latin-ext-400.css` declares a face with no `unicode-range` at all:

```css
@font-face { font-family: 'Nunito'; ... src: url(./files/nunito-latin-ext-400-normal.woff2) ...; }
```

Only the aggregated `400.css` carries the ranges, and there `latin-ext` explicitly starts at U+0100 while `latin` covers U+0000-00FF:

```
/* latin-ext */ unicode-range: U+0100-02BA, ...
/* latin     */ unicode-range: U+0000-00FF, U+0131, ...
```

The built output confirms no Latin face is produced — `build/_app/immutable/assets/0.4rJ3HW2b.css` contains 0 occurrences of `unicode-range` and the only Nunito files emitted are `nunito-latin-ext-*-normal.*` and `nunito-cyrillic-*-normal.*` (no `nunito-latin-*-normal.*`).

## Suggested fix

Import the Latin subset for every weight that is used (it also supplies `â`, `î`, `ä`, `ö`, `ü`, digits and ASCII punctuation):

```css
@import '@fontsource/nunito/latin-400.css';
@import '@fontsource/nunito/latin-600.css';
@import '@fontsource/nunito/latin-700.css';
@import '@fontsource/nunito/latin-800.css';
```

Keep `latin-ext` (for ș/ț/ă) and `cyrillic` (for ru). If the `unicode-range` guarantee in the comment matters, import the aggregated `@fontsource/nunito/400.css` etc. instead, which ships all three subsets with their ranges so a Latin-only locale never fetches the Cyrillic files.

## Test

Playwright assertion on any screen with Latin text:

```ts
const ranges = await page.evaluate(() =>
	[...document.fonts].map((f) => (f as FontFace & { unicodeRange?: string }).unicodeRange ?? '')
);
expect(ranges.some((r) => r.includes('U+0000'))).toBe(true); // a latin face is registered
```

and a build-time guard in `scripts/validate_assets.mjs`: `build/_app/immutable/assets` must contain a `nunito-latin-400-normal*.woff2` next to the `latin-ext` one.
